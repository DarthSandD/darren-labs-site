A desktop agent that lives on your machine.

Styx is a desktop agent that works on your machine. It runs its own gateway locally, keeps your sessions, skills, and scheduled jobs on your computer, and chats with the model provider you choose. You add your own provider key in Settings. Based on Nous Research Hermes Agent, MIT, upstream commit 25b5001.

What you get.

Your work stays on your machine.

Styx installs its backend on your computer and runs the gateway there. Your sessions, messages, artifacts, and scheduled jobs live locally. A charcoal square with an amber S, amber #d97706, marks it as Styx.

Set up once, then it just opens.

First run installs everything locally and takes several minutes. Later launches skip the install, because the backend is already there. Remote connections you already saved stay put.

Chat with the provider you choose.

Add your own model provider key in Settings, then chat. No provider key ships with Styx, and nothing is sent anywhere until you configure one. It opens fast, and stays readable if you prefer reduced motion.

How first run works.

First run needs internet once, and takes several minutes on a normal connection. A progress screen shows the nine stages. Do not close the app while it installs. When it finishes, the app opens to provider setup. Add your own model provider key in Settings, then chat. No provider key ships with Styx, and no prompt is sent anywhere until you configure one.

Limits to know.

  • Linux only in this release. Windows and macOS builds await verification.
  • Chat needs a provider key you supply. Add it in Settings at provider setup, then chat.
  • First install takes several minutes, longer on a slow connection. If the first connection attempt times out, Retry reconnects without reinstalling what already finished.
  • Styx shares the agent home at ~/.hermes with Hermes Agent, so the two use the same local backend.
